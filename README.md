# dsh-pet 🐳

Питомец для DeepSeek Harness: спрайт, который живёт **на рабочем столе** — поверх
всех окон, без рамки и без иконки в панели задач. Появляется сам при запуске DSH,
перетаскивается по всему экрану, думает вместе с агентом и превращается в галочку,
когда работа закончена.

| Состояние | Спрайт | Когда показывается |
|---|---|---|
| покой | `assets/Idle.gif` | агент простаивает |
| радость | `assets/alive.gif` | курсор наведён на питомца или по нему только что кликнули |
| думает | `assets/thinking.gif` | агент генерирует ответ |
| готово | `assets/done.gif`, затем `assets/float.gif` | работа завершилась: кит рассыпается искрами, галочка падает сверху и дальше левитирует |

Галочка **висит, пока её не подтвердят**, и не гаснет по таймеру. Подтверждение —
клик по питомцу (он же открывает последний рабочий чат) либо открытие переписки
самому. Новая работа тоже снимает галочку и включает «думает».

Превращение проигрывается **один раз**, после чего его сменяет бесшовная
левитация: если бы `done.gif` зацикливался, кит рассыпался бы искрами каждые
четыре секунды, пока ты читаешь ответ.

- **левая кнопка** — клик **поднимает окно DSH поверх остальных**, открывает
  последний рабочий чат и снимает галочку; перетаскивание двигает питомца по всему
  экрану (различаются по сдвигу окна)
- **правый клик или Esc** — закрывает питомца

## 1. Структура плагина

```
dsh-pet/
├── package.json          манифест: dsh.bundle.patch + dsh.client
├── cordis.patch.yml      host-половина: один insert в Loader
├── index.js              host-половина: окно, состояния, спрайты, маршруты
├── client.js             браузерная половина: статус агента и клик по питомцу
├── assets/
│   ├── Idle.gif          покой
│   ├── alive.gif         радость
│   ├── thinking.gif      раздумья: точки над головой
│   ├── done.gif          превращение кита в галочку (один раз)
│   └── float.gif         левитация галочки (цикл)
├── desktop/              мини-приложение Electron — сам питомец
│   ├── package.json
│   ├── main.js           прозрачное окно поверх всех, перетаскивание, клик
│   ├── preload.js        мостик contextIsolation → dragStart/dragEnd/close/onState/onFlash
│   └── pet.html          пять слоёв спрайтов и переключение состояний
├── test-client.mjs       30 проверок браузерной половины
├── test-host.mjs         42 проверки host-половины
├── test-desktop.mjs      29 проверок окна на рабочем столе
└── README.md
```

Ключевые поля `package.json` — без них DSH не увидит плагин:

```json
"exports": { ".": "./index.js", "./client": "./client.js" },
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "immediately": true, "inject": [] }
}
```

- `exports["./client"]` — точка входа браузерной половины (без неё не будет
  статуса агента).
- `dsh.bundle.patch` — по этому полю `dsh plugin add` понимает, что пакет является
  профильным слоем, и сам добавляет его в `dsh.profile.bundles`.
- `dsh.client.platform = "web"` — обязателен, иначе бандл не будет отдан в браузер.
- `files` перечисляет `desktop/**` — иначе папка не попадёт в пакет при установке
  через `file:` (при `link:` она линкуется целиком).

## 2. Установка

Плагин ставится в **профиль** — у Desktop-приложения он называется `desktop`
(`%USERPROFILE%\.dsh\profiles\desktop`).

### Способ A — через менеджер плагинов в интерфейсе

1. Открой DSH и зайди в **Plugins** в левой панели.
2. Нажми установку и вставь **абсолютный путь** к папке плагина.
3. Дождись окончания установки и перезагрузи страницу.

### Способ B — через терминал (встроенный CLI)

> ⚠️ **Сначала полностью закрой DSH**, включая иконку в трее. Профиль `desktop`
> принадлежит приложению, и CLI откажется работать, пока открыт файловый замок.

```powershell
$dsh = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop add "file:C:\путь\к\dsh-pet"
```

Удалить: `& $dsh plugin --profile desktop remove dsh-pet`.

### Как применить изменения после правки кода

- **`desktop/**`** читается заново при каждом создании окна — достаточно
  перезапустить питомца (правый клик и повторный запуск через `/show`) или
  перезагрузить плагин.
- **`client.js`** отдаётся по URL с ревизией из mtime — подхватится при перезагрузке
  страницы. В приложении пункта «обновить» нет, поэтому либо перезапуск DSH, либо
  выключить-включить плагин в Plugins.
- **`index.js`** грузится один раз при старте процесса, `dsh-hmr` в этом профиле
  сконфигурирован с `root: []` и за файлами не следит. Нужен перезапуск DSH или
  переключение плагина в Plugins.

## 3. Настройка

Размер, отступ и автостарт задаются в `cordis.patch.yml` профиля:

```yaml
- id: dsh-pet
  name: 'dsh-pet'
  config:
    size: 160       # сторона питомца в пикселях, по умолчанию 120
    margin: 32      # отступ от угла экрана, по умолчанию 24
    autoStart: true # false — не показывать питомца, пока не позовут
```

Питомец появляется в правом нижнем углу рабочей области основного экрана
(без учёта панели задач) и запоминает своё место, пока его не закроют.

## 4. Замена анимаций

Просто положи свои файлы поверх:

```
dsh-pet/assets/Idle.gif      покой
dsh-pet/assets/alive.gif     радость (курсор на питомце или клик)
dsh-pet/assets/thinking.gif  агент думает
dsh-pet/assets/done.gif      превращение кита в галочку (один раз)
dsh-pet/assets/float.gif     левитация галочки (цикл, пока её не подтвердят)
```

Имена должны остаться точно такими (регистр важен). После замены перезапусти
питомца — файлы читаются заново при каждом запуске окна.

Формат любой, который понимает браузер: GIF, APNG, WebP. Ограничение одно —
имя файла должно быть в белом списке `ASSETS` в `index.js`, а расширение задаёт
`Content-Type`. Если положишь `.webp`, добавь его в `ASSETS` и поправь карту
`SPRITES` в `desktop/main.js`.

Если положишь свои файлы, сгенерировать недостающие можно скриптом
`whale_states.py` в рабочей папке — он рисует `thinking.gif` и `done.gif` из
исходного спрайта кита.

### Главное при замене: все анимации должны иметь одинаковую рамку

Все спрайты вписываются в один и тот же квадрат через `object-fit: contain`,
поэтому **масштаб персонажа внутри кадра и его положение обязаны совпадать**.
Если `Idle.gif` нарисован «вплотную», а `done.gif` с запасом по краям, то при
переключении состояния персонаж визуально прыгнет в размере.

Отсюда требование: рисуй все анимации на **холсте одного размера**, ставя
персонажа в **одну и ту же точку**. Штатные ассеты так и сделаны — все четыре
720×720, кит в одинаковых координатах (по горизонтали занимает пиксели 132–587),
поэтому переключение ничего не двигает и не масштабирует.

### Как устроена анимация «готово»

Двумя файлами, а не одним. `done.gif` — одноразовая последовательность на 4.32
секунды: кит делает прощальный вдох, рассыпается искрами, галочка падает сверху с
небольшим перелётом. Дальше в дело вступает `float.gif` — бесшовный цикл на 2.16
секунды, где галочка просто левитирует вверх-вниз, как выпавший предмет в
Minecraft.

Разделение обязательно: галочка висит, пока её не подтвердят, а зацикленный
`done.gif` рассыпал бы кита искрами каждые четыре секунды всё это время. Окно само
переключает слой через `MORPH_MS` (4400 мс — чуть больше длины превращения) после
того, как host сообщил состояние `done`.

Галочка нарисована двумя толстыми штрихами, обводкой по контуру и подсветкой по
верхне-левому краю — так пиксель-арт сам себя затеняет. Движение задаётся синусом,
поэтому левитация плавная, а не рывками.

## 5. Как это работает

Всё ниже проверено по исходникам DSH в `app.asar` и на живом приложении.

### Почему питомец — отдельный процесс

**Страница не может рисовать за пределами своего окна.** Ни в браузере, ни в
Electron — это ограничение оконной модели.

**Host-плагины DSH не имеют API Electron.** Desktop-оболочка запускает всё рантайм
как дочерний node-процесс с `ELECTRON_RUN_AS_NODE=1`, так что `require('electron')`
внутри плагина — это обычный node. Создать окно «изнутри» нельзя.

**Отсюда архитектура:** host-половина запускает второе Electron-приложение
(`desktop/`) тем самым бинарником Electron, который поставляет сам DSH. Ищется он
в `<домашний каталог>/.dsh/electron/`, причём кандидат принимается только если
рядом лежит `resources/default_app.asar` — маркер «чистого» Electron. Без этой
проверки можно случайно взять `process.execPath`, а это упакованный
`DeepSeek Harness.exe`, который проигнорирует папку приложения и запустит сам себя.

### Восемь неочевидных деталей, каждая из которых ломала всё молча

**1. Снять `ELECTRON_RUN_AS_NODE`.**

```js
const env = { ...process.env }
delete env.ELECTRON_RUN_AS_NODE
```

Переменная унаследована от процесса DSH. Если её не снять, дочерний Electron не
создаст окно и молча завершится.

**2. Отключить аппаратное ускорение.**

```js
app.disableHardwareAcceleration()     // до app.whenReady()
```

Прозрачные окна на Windows композитятся через GPU, и на части драйверов этот путь
не даёт ничего: окно создано, `isVisible()` возвращает `true`, `capturePage()`
возвращает корректно отрисованный спрайт — а на рабочем столе пусто. Окно
переезжает на программный композит, и альфа начинает работать.

**3. Разрешить собственный скрипт в CSP страницы окна.**

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'none'; img-src file: data:; style-src 'unsafe-inline'; script-src 'unsafe-inline'">
```

`default-src 'none'` без `script-src` блокирует инлайн-скрипт самой страницы —
снова молча: спрайты не получают `src`, окно остаётся пустым. Заодно следите за
специфичностью CSS: `#pet img` специфичнее, чем `#idle`, поэтому правило покоя
должно быть не менее специфичным, иначе оба кадра останутся прозрачными.

**4. Двигать окно из главного процесса, а не по событиям страницы.**

Страница сообщает только «нажали» и «отпустили». Само движение производится в
главном процессе опросом реального курсора (`screen.getCursorScreenPoint()`):

```js
win.setPosition(cursor.x - offsetX, cursor.y - offsetY)
```

Если ждать `mousemove` со страницы, окно уезжает из-под курсора уже через
несколько пикселей, события прекращаются, и питомец замирает на полпути — ровно
это и выглядело как «не откликается на нажатие».

**5. Не рассчитывать на stdin дочернего Electron-процесса.**

```js
// так состояние до ребёнка НЕ дойдёт, хотя запись вернёт true
child.stdin.write(JSON.stringify({ state }) + '\n')
```

У главного процесса Electron `fd 0` — настоящая труба, `process.stdin`
существует, `setEncoding` и `resume()` отрабатывают без ошибок, но событие
`data` не приходит никогда. Запись на стороне host проходит успешно и исчезает
молча. Состояние передаётся опросом `GET /state` (раз в 0.7 с) — это работает.

**6. Не смешивать физические и логические пиксели.**

```js
const display = screen.getPrimaryDisplay()
const scale = display.scaleFactor          // здесь 2
const area = display.workArea              // 1536x912 — ФИЗИЧЕСКИЕ пиксели
options.x = Math.round(area.width / scale - SIZE - MARGIN)   // → 624, а не 1392
```

На экране с масштабом 200% Electron вернул рабочую область в **физических**
пикселях (1536×912), а координаты окна — в **логических** (768×456), и
`setPosition` принимает именно логические. Окно, поставленное в точку 1392
логических, оказывается на 2784 физических при экране 3072. Питомец создавался,
сообщал `isVisible() === true`, стоял поверх всех окон — и был **недостижим**:
курсор до него не дотягивался. Снаружи это неотличимо от «питомец игнорирует
мышь». Поэтому позиция ещё и прижимается к рабочей области.

Обратная сторона той же ловушки: у процессов, не осведомлённых о DPI,
координаты снимка экрана и `SetCursorPos` расходятся между собой. Автопроверка
наведения при этом «промахивается» мимо окна, которое прекрасно видно на
скриншоте, — и легко сделать вывод, что сломано приложение, а не тест.

**7. Поднять чужое окно можно только по праву переднего плана.**
```js
// питомец получил клик, значит он и есть процесс переднего плана;
// дочерний PowerShell наследует это право и может передать фокус дальше
spawn('powershell.exe', ['-Command', 'SetForegroundWindow(...)'])
```

Открыть чат недостаточно: если DSH свёрнут или позади браузера, `openSession`
переставляет окно, которого не видно, и клик выглядит мёртвым. Electron не умеет
фокусировать чужие окна, поэтому нужен Win32 — а Windows разрешает
`SetForegroundWindow` далеко не всем. Разрешение есть, если вызывающий процесс
сам на переднем плане **или запущен процессом на переднем плане**. Питомец как
раз получает клик, а PowerShell — его дочерний процесс, поэтому вызов проходит.
Из любого другого места он был бы молча проигнорирован.

Там же лежит вторая ловушка: полноэкранная игра на переднем плане **захватывает
курсор** (`ClipCursor`) так, что он физически не может добраться до питомца.
Снять захват вправе только процесс переднего плана. Именно из-за этого мои первые
автопроверки клика «промахивались» и выглядели как сломанный питомец.

**8. Окно питомца не должно активироваться, а жест — застревать.**

```js
focusable: false          // WS_EX_NOACTIVATE: клик доходит сразу, без активации
```

Окно, которое активируется по клику, тратит на это первое нажатие — и на этом
стиле окна оно до страницы не доходит. Снаружи выглядит так: после того как
что-то забрало фокус, первый щелчок по питомцу пропадает. Оверлейное окно
получает нажатие сразу. На подъём приложения это не влияет: Windows разрешает
`SetForegroundWindow` ещё и процессу, получившему последнее событие ввода, а его
это окно по-прежнему получает.

Рядом — вторая половина той же проблемы, уже в логике жеста. Отпускание кнопки
может уйти **другому окну**: во время перетаскивания питомец находится ровно под
курсором, и отпускание способно достаться тому, что окажется под ним. Если
защищаться флагом «уже тащим», питомец застревает в середине жеста, а плагин
помнит начало **прошлого** нажатия — и следующий честный клик измеряется как
огромное перетаскивание. Поэтому нажатие всегда начинает жест заново, а
отпускание без нажатия просто игнорируется.

### Статус агента

Статус приходит из браузерной половины: `useSessionStatus` — стандартный проп
слота, который ui-session публикует через `ctx.slots.provideRoot`. Это
селектор-хук над `Map<sessionId, { running, pendingInteraction, completionUnread }>`,
и `running === true` означает «генерирует ответ».

Браузерная половина **ничего не рисует**: она регистрируется в `shell.overlay`
ради получения этого пропа и отправляет каждое изменение на `POST /status`.

Дальше состояние живёт в host-половине, а окно забирает его само: раз в 0.7 с
спрашивает `GET /state` и переключает слой, если состояние изменилось.

Канал «host пишет строки в stdin ребёнка» был бы короче и **не работает**: у
главного процесса Electron `fd 0` действительно труба и `process.stdin`
существует, но событие `data` не приходит никогда — даже после явного
`resume()`. Записи на стороне host при этом проходят успешно и исчезают молча,
что снаружи выглядит ровно как «анимация просто не играет».

### Машина состояний

```
покой ──(агент начал работу)──► думает ──(работа закончилась)──► готово
  ▲                                                                │
  └────────(клик по питомцу или открытие переписки)────────────────┘
```

Реакция только на **смену** значения: во время длинной генерации браузерная
половина сообщает `running: true` сотни раз подряд, и пересылать это в окно
каждый раз незачем.

Состояние `done` **не имеет таймера**. Так было раньше — галочка гасла через
4.4 секунды, и это оказалось хуже: единственный признак, что ход завершился,
исчезал, пока ответ ещё читают. Теперь галочку снимает только пользователь:
клик по питомцу (`POST /open-chat`, он же открывает чат) или `POST /ack`, который
браузерная половина отправляет, когда переписка становится видимой. Новая работа
перебивает галочку в любом случае.

Курсор над питомцем перекрывает базовое состояние, но не заменяет его: когда
курсор уходит, возвращается то, что было, — «думает», «готово» или покой.

### Клик открывает последний рабочий чат

Питомец не может открыть чат сам: это отдельный процесс без доступа к интерфейсу,
а сервисы вроде `uiWorkspace` живут только в окне приложения. Поэтому клик идёт
по кругу:

1. Главный процесс мини-приложения сравнивает позицию окна в начале и в конце
   нажатия. Сдвиг меньше 6 px — это клик, больше — перетаскивание.
2. Он же поднимает окно DSH: см. ловушку 7 — право на это даёт сам факт клика.
3. `POST /open-chat` ставит флаг у host-половины.
4. Браузерная половина раз в 1.5 с забирает `GET /events`; чтение сбрасывает флаг,
   поэтому чат открывается ровно один раз.
5. Она выбирает сессию и вызывает `uiWorkspace.openSession(id)`.

Пункт 2 обязателен: без него клик по питомцу, когда DSH свёрнут или закрыт
браузером, открывал бы чат в невидимом окне — то есть не делал бы ничего заметного.

«Последний рабочий чат» — это сессия, открытая в основной области
(`retainedBy.mainView > 0`), а если такой нет — самая недавно обновлённая по
`updatedAt`. Если сервиса `uiWorkspace` нет, вызывается `layout.selectPanel(null)`:
панель беседы всё равно выходит вперёд, чтобы клик не пропал впустую.

### Маршруты

| Маршрут | Назначение |
|---|---|
| `POST /api/dsh-pet/status` | браузерная половина сообщает `{running}` |
| `GET /api/dsh-pet/state` | `{alive, running, state}` |
| `GET /api/dsh-pet/events` | браузерная половина забирает клик; чтение сбрасывает флаг |
| `POST /api/dsh-pet/open-chat` | питомец сообщает, что по нему кликнули; снимает галочку |
| `POST /api/dsh-pet/ack` | пользователь открыл переписку сам — снять галочку |
| `POST /api/dsh-pet/show` | поднять окно (`{size, margin, x, y}`) |
| `POST /api/dsh-pet/hide` | снять окно вместе с деревом процессов |
| `GET /api/dsh-pet/assets/<имя>` | отдать спрайт (белый список из пяти имён) |

Одновременно живёт ровно один питомец: `startPet` сначала **дожидается** выхода
предыдущего процесса, иначе два окна висят на экране, пока старое не умрёт.

## 6. Тесты

```powershell
$node = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
& $node dsh-pet\test-client.mjs    # 30 проверок: слот, статус, опрос клика, выбор чата
& $node dsh-pet\test-host.mjs      # 42 проверки: машина состояний, маршруты, обход пути
& $node dsh-pet\test-desktop.mjs   # 29 проверок: окно, пять слоёв, превращение, перетаскивание
```

`test-client.mjs` подменяет `window.__ModuleLoader__` и React минимальным runtime
хуков, а `setInterval` — управляемым, поэтому опрос клика проигрывается по шагам,
а не ожиданием. `test-host.mjs` монтирует плагин на фейковый web-сервер с
`autoStart: false` и укороченным `doneMs: 60`, чтобы во время теста ничего не
всплывало на экране и не приходилось ждать 4 секунды. `test-desktop.mjs` поднимает
настоящее окно примерно на секунду и проверяет всю цепочку: поиск бинарника,
создание окна, декодирование всех четырёх спрайтов, переключение слоёв, отрисовку,
видимость, «поверх всех» и перетаскивание. Его нужно запускать вне песочницы, иначе
Electron не сможет создать процесс.

## 7. Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| Питомца нет вообще | `dsh-pet` не в `dsh.profile.bundles` профиля, либо `DSH_HOME` не найден. Проверь `/api/dsh-pet/state`. |
| `{"ok":false,"error":"electron runtime not found"}` | Нет `%USERPROFILE%\.dsh\electron\electron.exe` или у него нет `resources/default_app.asar`. |
| Окно есть, но пустое | Заблокирован скрипт страницы (CSP) или спрайт не декодировался. Запусти `test-desktop.mjs` — он это проверяет. |
| Окно вообще не видно | Включено аппаратное ускорение. Нужен `app.disableHardwareAcceleration()`. |
| Питомец есть в диспетчере, но его не видно и он не ловит мышь | Позиция посчитана в физических пикселях вместо логических — окно уехало за край экрана. Делите `workArea` на `scaleFactor`. |
| Виден не тот спрайт или видно два сразу | Ошибка специфичности CSS: `#pet img` перебивает правило состояния. Нужны селекторы вида `body[data-state="…"] #pet #…`. |
| Перетаскивание замирает на полпути | Движение берётся из событий страницы вместо опроса курсора в главном процессе. |
| Питомец улетает за край при перетаскивании | Один замер курсора пришёл в других единицах (обычно из-за захвата курсора игрой). Движение должно применяться дельтой и с отсечкой абсурдных скачков. |
| Клик не поднимает окно DSH | `SetForegroundWindow` разрешён только процессу переднего плана или запущенному им. Значит вызов идёт не сразу после клика по питомцу, а из другого места. |
| Первый клик после перетаскивания пропадает | Либо окно активируется по клику (нужен `focusable: false`), либо жест застрял из-за потерянного отпускания (нажатие должно начинать жест заново). |
| Два питомца | `startPet` не дождался выхода предыдущего процесса перед запуском нового. |
| Клик не открывает чат | Проверь `POST /open-chat`, затем `GET /events`. Если флаг приходит, а чат не открывается — нет сервиса `uiWorkspace` или не нашлась сессия. |
| Клик вроде бы «ничего не делает» | Скорее всего чат и был открыт — и это единственная сессия. Поэтому клик ещё и снимает галочку, и питомец коротко радуется: без видимого отклика исправный клик неотличим от сломанного. |
| Не показывается «думает» | Статус не доходит: проверь `POST /status` и что `useSessionStatus` есть среди пропов. |
| Галочка исчезает сама | Так было до версии без таймера. Сейчас её снимает только клик по питомцу, открытие переписки или новая работа. |
| Превращение проигрывается по кругу | Слой не переключился с `done.gif` на `float.gif`: проверь `MORPH_MS` и что `float.gif` вообще отдаётся. |
| Питомец не отзывается на мышь | Окно потеряло фокус или его перекрыло окно с более высоким уровнем. Оно ставится на уровень `screen-saver`. |

Полезные команды:

```powershell
$dsh = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop list
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\.plugin-manager\logs\*\pnpm.log"
```
